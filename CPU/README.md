# 🧠 Процессоры — бенчмарки `hashcat -b`

Раздел процессоров. Raw-вывод сохраняется дословно, когда он опубликован.
Для полноты каталога допустимы отдельные `.md`-карточки с частичными фрагментами,
PTS/официальными отчётами и community comparison-таблицами — тип данных и
ограничения обязательно указываются в карточке. Они не смешиваются с raw и не
попадают в сопоставимый ranking без достаточных условий теста.

## Структура

```
CPU/
├── Intel/
│   ├── Core i9/
│   │   └── Intel Core i9-13900K/
│   │       └── Intel Core i9-13900K — <автор> v<версия>.md
│   ├── Core i7/
│   ├── Core Ultra/
│   └── Xeon/
└── AMD/
    ├── Ryzen 9/
    ├── Ryzen 7/
    ├── Threadripper/
    └── EPYC/
```

Три уровня: **вендор → семейство → модель**. Внутри папки модели — один или
несколько документов от разных источников, версий hashcat и конфигураций.
Разбивка по семействам нужна, потому что плоский список на несколько тысяч
моделей нечитаем и обрезается веб-интерфейсом GitHub (лимит ~1000 записей
на директорию).

Имя файла: `<полное имя CPU> — <источник> <версия>.md`.

## Особенности CPU-прогонов

В отличие от видеокарт, у процессоров чаще встречаются нюансы, которые
**обязательно** выносить отдельной строкой в шапку файла:

- Бэкенд — обычно `OpenCL API ... [The pocl project]` или `[Intel(R) CPU Runtime]`;
  устройство выглядит как `pthread-<модель>`.
- Число задействованных потоков и `-T` / `--backend-devices`, если задавались.
- Прогон часто идёт **вместе с GPU** — тогда брать нужно строку `Speed.#N`
  именно CPU-устройства, и только если сопоставление однозначно.
- Многие публичные CPU-прогоны **неполные** (один-два режима) — это допустимо,
  но помечается в шапке и в сводной таблице.
- Сравнительная таблица без stdout/методики (например, mode 22000 из Gist)
  хранится как **community comparison**, а не как подтверждённый raw-бенчмарк.
